#### File Descriptors and Redirections
- File Descriptor (FD) - unique identifier
- that allows system to manage I/O operations. Managed by kernel. 
- can be used for open file, socket or any other I/O resource
- Windows calls it file handle
- system uses this to keep track of active I/O connections, e.g. reading from or writing to a file
- First three file descriptions in Linux:
	- Data stream for input STDIN - 0
	- Data stream for output STDOUT - 1
	- Data stream for output that relates to an error occurring STDERR - 2
#### STDIN and STDOUT
- when running cat, we give the running program our standard input (STDIN -FD 0). When confirming input by pressing ENTER, it is returned to the terminal as standard output (STDOUT - FD 1)
#### STDOUT and STDERR
- error can be discarded by redirecting the file descriptor for the rrors (FD 2 - STDERR) to /dev/null (null device) by marking 2>/dev/null
- STDOUT can be redirected to results.txt by `> results.txt`
- E.g. `naisa6@htb[/htb]$ find /etc/ -name shadow 2>/dev/null > results.txt`
- number is not specified before greater-than sign above because all standard errors were redirected to the null device and the only output left is standard output. To be more precise, can use 2> stderr.txt 1> stdout.txt
#### Redirect STDIN Stream to a File
- `<<`- add standard input through a stream 
- `End-Of-File` (`EOF`) function of a Linux system file, defines the input's end
- `naisa6@htb[/htb]$ cat << EOF > stream.txt` use the `cat` command to read our streaming input through the stream and direct it to a file called "`stream.txt`."
#### Pipes
- `|` - redirect `STDOUT`. Useful when we want to use the `STDOUT` from one program to be processed by another.
- Grep - used to filter `STDOUT` according to the pattern we define.
- E.g. `find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l`

#### Filter Contents
- two pagers - `more` and `less` - view contents of a file interactively, one screen at a time.
- less has more than more
- `head` - by default, prints first ten lines of given file or input.
- `tail` - by default, prints last ten lines
- `sort` - sort alphabetically (or numerically)
- `grep` - `cat /etc/passwd | grep "/bin/bash"` - search for users who have their default shell set to `/bin/bash`
- `grep -v` -  exclude specific result. E.g. `cat /etc/passwd | grep -v "false\|nologin"` - exclude all users who have disabled the standard shell with the name "`/bin/false`" or "`/usr/bin/nologin`".
- `cut` - specific results with different characters may be separated as delimiters. 
  E.g. `cat /etc/passwd | grep -v "false\|nologin" | cut -d":" -f1` 
  option "`-d`"  set delimiter to the colon character (`:`), define with option "`-f`"  position in  line to output
- `tr` - first option - define which character to replace, second option - define the character to replace it with. E.g. `cat /etc/passwd | grep -v "false\|nologin" | tr ":" " "` - replace the colon character with space.
- `column` - display results in tabular form using -t option. E.g. `cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | column -t`
- `awk` - display the first (`$1`) and last (`$NF`) result of the line. E.g. `cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | awk '{print $1, $NF}'`
-  `sed` - stream editor that allows substituting text. Looks for patterns defined in the form of regex and replaces with another pattern defined. s flag is substitute command and g flag stands for replacing all matches. E.g. `cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | awk '{print $1, $NF}' | sed 's/bin/HTB/g'`
- `wc` - count successful matches. -l option specifies that only lines are counted.
- ss -l -4 -l: show only listening services -4: show only ipv4 E.g. ss -l -4 | grep -v "127.0.0" | grep "LISTEN" | wc -l
- `curl "https://www.inlanefreight.com" | tr " " "\n" | tr "\'" "\"" | grep "https://www.inlanefreight.com" | tr "\"" " " | awk '{print $2}' | sort -u `
- Regex - find, replace, manipulate data.   

| Operators | Description                                                                                                                                                                 |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `(a)`     | The round brackets are used to group parts of a regex. Within the brackets, you can define further patterns which should be processed together.                             |
| `[a-z]`   | The square brackets are used to define character classes. Inside the brackets, you can specify a list of characters to search for.                                          |
| `{1,10}`  | The curly brackets are used to define quantifiers. Inside the brackets, you can specify a number or a range that indicates how often a previous pattern should be repeated. |
| \|        | Also called the OR operator and shows results when one of the two expressions matches                                                                                       |
| `.*`      | Operates similarly to an AND operator by displaying results only when both expressions are present and match in the specified order                                         |
|           |                                                                                                                                                                             |
	E.g. `grep -E "(my|false)" /etc/passwd` - search for lines containing the word `my` or `false`. apply the extended regex using the `-E` option in grep
	E.g. 2 `grep -E "(my.*false)" /etc/passwd` - line with both `my` and `false`
