#### Network Access Control

| Type                                 | Description                                                                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Discretionary Access Control (`DAC`) | This model allows the owner of the resource to set permissions for who can access it.                                     |
| Mandatory Access Control (`MAC`)     | Permissions are enforced by the operating system, not the owner of the resource, making it more secure but less flexible. |
| Role-Based Access Control (`RBAC`)   | Permissions are assigned based on roles within an organization, making it easier to manage user privileges.               |
- security policies like `SELinux` (Security-Enhanced Linux), `AppArmor` profiles for application security, and using `TCP wrappers` to control access to services based on IP addresses
- Tools such as `syslog`, `rsyslog`, `ss` (for socket statistics), `lsof` (to list open files), and the `ELK stack` (Elasticsearch, Logstash, and Kibana) can be used to monitor and analyze network traffic.
- `ping` to check network connection, `nslookup` to query Internet name servers interactively and `nmap` to detect vulnerable entrances.  
#### Configuring Network Services
- local network interfaces can be configured using the `ifconfig` or the `ip` command.  `ifconfig` command - information regarding network interfaces, such as IP addresses, netmasks, and status.  `ip` command replaces `ifconfig` and offers more advanced features. 
- Network settings - network interfaces can be activated by both commands.
- Activating Network Interface

| ifconfig                | ip                         |
| ----------------------- | -------------------------- |
| `sudo ifconfig eth0 up` | `sudo ip link set eth0 up` |
- Assign IP Address to an Interface - `sudo ifconfig eth0 192.168.1.2`
- Assign a Netmask to an Interface - `sudo ifconfig eth0 netmask 255.255.255.0`
   route command with the add option -  set the default gateway for a network interface. gateway's IP address and the network interface to which it should be applied can be specified.
   By setting the default gateway, IP address of the router that will be used to send traffic to destinations outside the local network is designated. Ensuring that the default gateway is set correctly is important, as incorrect configuration can lead to connectivity issues.
- Assign the Route to an Interface - `sudo route add default gw 192.168.1.1 eth0`
  Domain Name System (`DNS`) servers need to be set to ensure proper network functionality.
  Proper DNS configuration is crucial for enabling devices to access websites, online services, and other networked resource. `/etc/resolv.conf` file contains the system’s DNS information.
- Editing DNS Settings - `sudo vim /etc/resolv.conf`. Edit `/etc/network/interfaces` file to ensure that these changes are saved to persist across reboots. Changes to `/etc/resolv.conf` file are not persistent across reboots or network configuration changes because the file may be automatically overwritten by network management services like `NetworkManager` or `systemd-resolved`. To fix this, configure DNS settings through the appropriate network management tool, such as editing network configuration files or using network management utilities that store persistent settings.
- Editing Interfaces - `sudo vim /etc/network/interfaces` - opens the `interfaces` file in the vim editor. Network configuration settings can be added to the file e.g.
  /etc/network/interfaces
```
auto eth0
iface eth0 inet static
  address 192.168.1.2
  netmask 255.255.255.0
  gateway 192.168.1.1
  dns-nameservers 8.8.8.8 8.8.4.4
```
 - By setting the `eth0` network interface to use a static IP address of `192.168.1.2`, with a netmask of `255.255.255.0` and a default gateway of `192.168.1.1`, network connection remains stable and reliable. By specifying DNS servers of `8.8.8.8` and `8.8.4.4`, computer can easily access the internet and resolve domain names. After saving, restart the networking service to apply the changes. `sudo systemctl restart networking`

#### Network Access Control
- Discretionary Access Control - provide access to their resources while managing the associated risks of unauthorized access. Enables users to manage access to their resources by granting resource owners the responsibility of controlling access permissions to their resources.
- Mandatory Access Control -  more fine-grained control over resource access than DAC systems. Define rules that determine resource access based on the resource's security level and the user's security level or process requesting access. Each resource is assigned a security label that identifies its security level, and each user or process is assigned a security clearance that identifies its security level.  Access to a resource is only granted if the user's or process's security level is equal to or greater than the security level of the resource.
- Role-based Access Control - assigns permissions to users based on their roles within an organization, each user is assigned one or more roles, each role is granted a set of permissions that determine the actions they can perform. Simplifies the management of access permissions, reduces the risk of errors, and ensures that users can access only the resources necessary to perform their job functions

#### Troubleshooting
- involves diagnosing and resolving network issues that can adversely affect the performance and reliability of the network. Common tools: Ping, Traceroute, Netstat, Tcpdump, Wireshark, Nmap
- `traceroute` - traces the route packets take to reach a remote host. It sends packets with increasing Time-to-Live (TTL) values to a remote host and displays the IP addresses of the devices that the packets pass through. Output provides a detailed view of the path packets take to reach the Inlanefreight web server. No response from the device at that hop, indicated by the three asterisks instead of the IP address could mean the device is down, blocking ICMP traffic, or a network issue caused the packets to drop.
- `netstat` - display active network connections and their associated ports, identify network traffic and troubleshoot connectivity issues. Protocol used, the number of bytes received and sent, IP addresses, port numbers of both local and remote devices, and the current connection state.
- common network issues:
	-  Network connectivity issues
	- DNS resolution issues (it's always about DNS)
	- Loss of data packets
	- Network performance issues
- common causes:
	- Incorrectly configured firewalls or routers,
	- damaged network cables or connections,
	- incorrect network settings,
	- hardware failures,
	- incorrect DNS server settings or DNS server failures
	- incorrectly configured DNS entries,
	- network congestion,
	- outdated network hardware or incorrectly configured network settings,
	- unpatched software or firmware and missing security controls.
#### Hardening
- Security-Enhanced Linux - mandatory access control (`MAC`) system integrated into the Linux kernel, enforces security policies, which define the permissions for each process and file on the system, significantly limiting the damage that a compromised process or service can do. Operates at a low level, and though it offers strong security, it can be complex to configure and manage due to its granular controls. 
  Installing: `sudo apt update && sudo apt install policycoreutils selinux-basics selinux-utils auditd -y
  Activating: `sudo selinux-activate`
  Configuring: `sudo nano /etc/selinux/config` `SELINUX=disabled` change it to `permissive`
  Relabel - Before SELinux can be fully enforced, every file on your filesystem must be labeled with an SELinux context. Create an empty `.autorelabel` file in your root directory to instruct the system to relabel everything upon the next boot `sudo touch /.autorelabel`
  Reboot: `sudo reboot
  Check: `sestatus`
- AppArmor - MAC system that controls access to system resources and applications, but it operates in a simpler, more user-friendly manner. AppArmor is implemented as a Linux Security Module (`LSM`) and uses application profiles to define what resources an application can access.
- TCP Wrappers - host-based network access control tool that restricts access to network services based on the IP address of incoming connections. TCP wrappers intercept network request and checks it against a list of allowed or denied IP addresses.

#### Remote Desktop Protocols
-  provide graphical remote access to a system
	-  `Remote Desktop Protocol` (`RDP`): Primarily used in Windows environments. RDP allows administrators to connect remotely and interact with a Windows desktop.
	- `Virtual Network Computing` (`VNC`): A popular protocol in Linux environments, although it is also cross-platform. VNC provides graphical access to remote desktops, allowing administrators to perform tasks on Linux systems in a similar way to RDP on Windows.
- XServer -  user-side part of the `X Window System network protocol` (`X11` / `X`). `X11` is a fixed system that consists of a collection of protocols and applications that allow us to call application windows on displays in a graphical user interface. Mainly uses TCP/IP (TCP/6001-6009) as a transport base but can also be used on pure Unix sockets. When starting a new desktop session via X server the `TCP port 6000` would be opened for the first X display `:0`, enables the server to perform its tasks such as hosting applications, as well as providing services to clients. They are often used to provide remote access to a system, allowing users to access applications and data remotely.
  Unencrypted - but can be encrypted by tunneling the SSH protocol. Allow X11 forwarding in the SSH configuration file (`/etc/ssh/sshd_config`) on the server that provides the application by changing this option to `yes`.  `cat /etc/ssh/sshd_config | grep X11Forwarding`
  ssh -X htb-student@10.129.23.11 /usr/bin/firefox
- XDMCP - `X Display Manager Control Protocol` (`XDMCP`) protocol is used by the `X Display Manager` for communication through UDP port 177 between X terminals and computers operating under Unix/Linux. Used to manage remote X Window sessions on other machines and is often used by Linux system administrators to provide access to remote desktops.  Possible to redirect an entire graphical user interface (`GUI`) (such as KDE or Gnome) to a corresponding client. For a Linux system to act as an XDMCP server, an X system with a GUI must be installed and configured on the server. Attacker can intercept the communication between the remote computer and the X Window System server, and impersonate one of the parties in order to gain unauthorized access to the server.
- VNC - `Virtual Network Computing` (`VNC`) is a remote desktop sharing system based on the RFB protocol that allows users to control a computer remotely. One of the most common protocols for remote graphical connections for Linux hosts. Uses encryption to ensure the data is safe while in transit and requires authentication before a user can gain access. 
  Two different concepts for VNC servers. The usual server offers the actual screen of the host computer for user support. Because the keyboard and mouse remain usable at the remote computer, an arrangement is recommended. The second group of server programs allows user login to virtual sessions, similar to the terminal server concept.
  Traditionally, the VNC server listens on TCP port 5900. So it offers its `display 0` there. Other displays can be offered via additional ports, mostly `590[x]`, where `x` is the display number.
  Different VNC tools: [TigerVNC](https://tigervnc.org/), [TightVNC](https://www.tightvnc.com/), [RealVNC](https://www.realvnc.com/en/), [UltraVNC](https://uvnc.com/)
