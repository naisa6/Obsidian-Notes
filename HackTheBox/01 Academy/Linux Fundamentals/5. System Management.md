#### Permission Management
- assigned to both users and groups
- determines reading, writing or executing file
- new file or directory created automatically owned by creator]
- to access directory, user must have execute permission. Execute permissions on a directory do not allow a user to execute or modify any files or contents within the directory, only to traverse and access the content of the directory.
- to execute files within the directory, a user needs execute permissions on the corresponding file. To modify contents of a directory (create, delete, rename files and subdirectories), the user needs write permissions on the directory.
- permission system is based on octal number system. Permissions can be set for the owner, group and others. 
- ![[Pasted image 20260530232544.png]]
- modify permissions using the chmod command, permission group reference (`u` - owner, `g` - Group, `o` - others, `a` - All users) and eitehr a + or - to add or remove the permissions. E.g. `chmod a+r shell && ls -l shell`
- octal value assignment: 

| Binary Notation:           | 4 2 1 | 4 2 1 | 4 2 1 |
| -------------------------- | ----- | ----- | ----- |
| Binary Representation:     | 1 1 1 | 1 0 1 | 1 0 0 |
| Octal Value:               | 7     | 5     | 4     |
| Permission Representation: | r w x | r - x | r - - |
- Change owner - chown
  E.g. `chown <user>:<group> <file/directory>`
- SUID & SGID - configure special permissions on files through the Set User ID (SUID) or Set Group ID (SGID) bits. function like temporary access passes, enabling users to run certain programs with the privileges of another user or group. E.g. administrators can use `SUID` or `SGID` to grant users elevated rights for specific applications, allowing tasks to be performed with the necessary permissions, even if the user themselves doesn’t normally have them. Presence of these permissions is indicated by an `s` in place of the usual `x` in the file's permission set. When a program with the SUID or SGID bit set is executed, it runs with the permissions of the file's owner or group, rather than the user who launched it.
- Sticky bits - like locks on files within shared spaces. When set on a directory, the sticky bit adds an extra layer of security, ensuring that only certain individuals can modify or delete files, even if others have access to the directory. T - all other users do not have execute permissions, cannot see the contents of the folder nor run any programs from it. Lowercase t is the sticky bit where the execute permissions have been set.

#### Services
- aka Daemons, fundamental components that run silently in the background without direct  user interaction.
- System Services - internal services required during system startup. Perform essential hardware-related tasks and initialise system components necessary for the OS to function. 
- User-installed services - added by users, e.g. server applications and other background processes that provide specific features or capabilities. 
- Daemons are identified by the letter d at the end of their program names, e.g. sshd (SSH daemon) or systemd. 
- When dealing with services, the options are to:
	1. start/restart a service/process
	2. stop a service/process
	3. see what is/was happening with a service/process
	4. enable/ disable a service/ process on boot
	5. find a service/ process
- Most modern Linux distros have systemd as t heir initialisation system (init system). First process that starts during the boot process and is assigned the process ID (PID). Process IDs can be viewed under the /proc/ directory
- Systemctl - systemctl can be used to start (start), view status (status), add to SysV script to run service at startup (enable), list all services (list-units --type=service). Can use journalctl to view logs if there is an error e.g. `journalctl -u ssh.service --no-pager` 
- ps -aux | grep program_name 
- Process can be in one of the following states: Running, Waiting (waiting for an event or system resource), Stopped, Zombie (stopped but still has an entry in the process table.). Processes can be killed with kill, pkill, pgrep, and killall. View all signals with kill -l

| Signal | Description                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| 1      | `SIGHUP` - This is sent to a process when the terminal that controls it is closed.                                       |
| 2      | `SIGINT` - Sent when a user presses `[Ctrl] + C` in the controlling terminal to interrupt a process.                     |
| 3      | `SIGQUIT` - Sent when a user presses `[Ctrl] + D` to quit.                                                               |
| 9      | `SIGKILL` - Immediately kill a process with no clean-up operations.                                                      |
| 15     | `SIGTERM` - Program termination.                                                                                         |
| 19     | `SIGSTOP` - Stop the program. It cannot be handled anymore.                                                              |
| 20     | `SIGTSTP` - Sent when a user presses `[Ctrl] + Z` to request for a service to suspend. The user can handle it afterward. |
- e.,g. can kill program with `kill 9 <PID>`
- Background a process - Can use shortcut `[Ctrl + Z]`, which sends the SIGTSTP signal to the kernel. All background processes can be displayed with `jobs`. To keep it running in the background, enter `bg` to put process in the background. Another option is to set the process with `&` at the end e.g. `ping -c 10 www.hackthebox.eu &`, which will show the results once done.
- Foreground a process - use `jobs` to list, `fg <ID>`
- Execute multiple commands - three ways to do this are: Semicolon (`;`), Double `ampersand` characters (`&&`), Pipes (`|`). 
  `;`Semicolon - command separator and executes the commands by ignoring previous commands' results and errors.. 
  `&&` Double ampersand - If there is an error in one of the commands, the following ones will not be executed anymore, and the whole process will be stopped.
  `|` Pipe - depend not only on the correct and error-free operation of the previous processes but also on the previous processes' results.

#### Task Scheduling
- allows task automation with specific times/ regular intervals. 
- can serve both as a legitimate administrative tool and a vector for malicious activity, e.g. unauthorized cron jobs that execute harmful scripts or maintain persistent backdoors at scheduled intervals
- Systemd - used in some Linux systems to start processes and scripts at specific times. Three steps: 1. create a timer (schedules when your `mytimer.service` should run), 2. Create a service, (executes the commands or script) 3. Activate the timer.
  Create a Timer - create a directory where the timer script will be stored
  `sudo mkdir /etc/systemd/system/mytimer.timer.d && sudo vim /etc/systemd/system/mytimer.timer`. Create a script that configures the timer. Script must contain: "Unit", "Timer" and "Install". The "Unit" option specifies a description for the timer. The "Timer" option specifies when to start the timer and when to activate it. Finally, the "Install" option specifies where to install the timer. 
  E.g. 
  ```
  [Unit] Description=My Timer
  [Timer] OnBootSec=3min OnUnitActiveSec=1hour 
  [Install] WantedBy=timers.target
  ```
  if script should run only once after the system boot, use `OnBootSec` setting in `Timer`. However, if script should run regularly, then use `OnUnitActiveSec` to have the system run the script at regular intervals.
  Create a Service `sudo vim /etc/systemd/system/mytimer.service`
  Set a description and specify the full path to the script we want to run. The "multi-user.target" is the unit system that is activated when starting a normal multi-user mode. It defines the services that should be started on a normal system startup.
  ```
  [Unit]
  Description=My Service
  
  [Service]
  ExecStart=/full/path/to/my/script.sh
  
  [Install]
  WantedBy=multi-user.target
  ```
  After that, let `systemd` read the folders again to include the changes.
  Start the Timer & Service
  ```
  sudo systemctl start mytimer.timer && sudo systemctl enable mytimer.timer
  ```
  `mytimer.service` will be launched automatically according to the intervals (or delays) you set in `mytimer.timer`
  
 - Cron - another tool that can be used in Linux systems to schedule and automate processes. Create a script and then tell the cron daemon to call it at a specific time. Store the tasks in a file called `crontab` and tell the daemon when to run the tasks. Schedule and automate the tasks by configuring the cron daemon accordingly. 

| **Time Frame**         | **Description**                                                       |
| ---------------------- | --------------------------------------------------------------------- |
| Minutes (0-59)         | This specifies in which minute the task should be executed.           |
| Hours (0-23)           | This specifies in which hour the task should be executed.             |
| Days of month (1-31)   | This specifies on which day of the month the task should be executed. |
| Months (1-12)          | This specifies in which month the task should be executed.            |
| Days of the week (0-7) | This specifies on which day of the week the task should be executed.  |
- e.g. 0 /6 means once every 6th hour.
